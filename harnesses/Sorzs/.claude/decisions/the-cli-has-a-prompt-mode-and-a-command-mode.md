# The CLI has a prompt mode and a command mode

`sorzs` with no arguments opens the prompt, as before. `sorzs <command> [arguments]` runs that one command and ends, with no prompt, no history and no Tab. Command mode never asks anything: `login` reads `SORZS_USER` and `SORZS_PASSWORD`, a missing or forbidden pass fails asking for `login`. Results go to stdout, errors to stderr, exit code 0 or 1. `exit` exists only in the prompt. `help` lists the same descriptions in both modes; command mode prefixes each with `sorzs ` and leaves `exit` out. Why: agents and scripts need to call each command from a shell without driving a prompt; the prompt stays for people, who enter once per run. Credentials come from the environment so the password never lands in the shell history or the process list. No JSON output until a command returns data that needs it. Every failure goes through one path in both modes, so the exit code needs no wiring per command; the prompt shows the same lines, now on the error output.
