# The Users section operations require the admin role

`ProtectedOperation` takes the role the operation requires (any user, or admin). For an admin operation it reads the role of the token's user from `Users` on every call and answers the same `FORBIDDEN` as a missing token when the role is not admin. `users.list`, `users.add` and `users.setRole` require admin; the source and search operations stay open to any authenticated user. The token still carries no role. Why: reading the role per call makes a role change count from the next request, with nothing to expire or revoke, and one forbidden answer is what the frontend already handles by forgetting the pass (`session.md`). A new error code for "wrong role" was rejected: the caller can do nothing different with it.
