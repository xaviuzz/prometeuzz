# Components grouped by feature

`src/components/` holds one component per file, in `layout/` (`Header`, `HealthMark`), `catalogue/` (`Catalogue`, `AlbumRow`, `AlbumCard`) and `making/`; `test/components/` mirrors it. `making/` splits into `face/` (`FaceViewer`, `FaceView`, `FaceNavigation`, `FaceNumber`) and `photos/` (`PhotoTray`, `PhotoThumbnails`, `RejectedFiles`, `rejectionReason`, `UploadButton`), one folder per ensemble; `MakingHeader` stays at the root of `making/` because it belongs to neither. A feature folder splits into ensemble folders when its components form groups that change together. A component that two features share sits at the root of `src/components/`, beside the feature folders (`ReadingView`, `LoadingNotice`, `FailureNotice`, `EmptyNotice`); see [Reading states live in one ReadingView](reading-states-live-in-one-reading-view.md). Where a helper that is not a component lives: [Domain folder and colocated helpers](domain-folder-and-colocated-helpers.md). Why: what changes together lives together; a flat `making/` mixed two groups of components that never reference each other.
