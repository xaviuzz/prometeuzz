# The Sorzs section reads a SourceCensus

One operation, `sorzs.sources`, requires admin and answers `{ sources: [{ address, favicon, users }] }`, already ordered; `favicon` is null only in the contract. In the domain, `SourceCensus` groups the entries of every user by source, counts distinct users and orders by address ignoring case. To feed it, `SourceListRepository` gains a read of the entries of all owners: `SqliteSourceListRepository` only reads, and `InMemorySourceListRepository` hands over what it holds. Why: the section is a resource of its own, as `users.*` is, and the frontend only paints. The rule lives in the domain and is tested once with the in-memory repository, with no SQL; the stores differ only in where the entries are kept, as with `Roster` for users. Ordering in the frontend was rejected: the order is a rule of the census. A GROUP BY in SQLite was rejected: the in-memory store would lack the rule and the count would drift between stores. Pagination was left out: the number of sources of two users does not need it.
