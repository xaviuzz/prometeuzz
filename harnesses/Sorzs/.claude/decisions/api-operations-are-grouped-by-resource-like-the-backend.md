# API operations are grouped by resource, like the backend

Each operation of the frontend `api/` sits in a folder named for its resource (`sources/`, `health/`), the same grouping as the backend's `operations/`. `Api`, `ApiContext`, `CallRefusedError`, `Refusable`, `CallId` and the generated `schema.d.ts` stay at the root. A new operation goes in its resource's folder, and its test mirrors it under `test/api/`. Why: an operation is found the same way in both repos (`SearchSources` is a sources operation in both), and a flat folder got harder to scan with every operation. Grouping by technical type was rejected because each folder would hold one file. Moving `schema.d.ts` into a `generated/` folder was rejected: it changes the paths in `generate` and `generate:check` for little gain.
