# API wrappers throw refusals and let network failures through

`AddSource`, `InspectSource`, `ListSources` and `SearchSources` throw `CallRefusedError` (code and message) for an `error` reply and for the 400 transport error, and let a `fetch` failure reach the caller as it is. The add dialog and the side bar show `error.message` for both through `messageOf`; the dialog's inspect swallows it (`stale-inspect-replies-are-discarded`). Why: a refusal and a failure are both something to show, and the caller has nothing to do differently, so one `catch` serves both. `HealthCheck` keeps answering `ok` or `error` without throwing because the mark only needs the state, not a message.

Each operation opens its reply through `Refusable`, which returns the success body or throws; the route, payload and mapping stay in the operation. Composition, not a base class: the `run` signatures differ, `openapi-fetch` types each route on its own so a generic base would need conditional types, and the project prefers composition over inheritance.
