# A SourcesProvider owns the reading; the dialog reports what it added

`SourcesProvider` keeps the reading of the list (loading, loaded, failed), each a `SourceReading` that renders itself and returns a new reading from `append(entry)`. `useSourceReading` gives it to the side bar and `useAppendSource` to the header. `AddSourceDialog` takes `onAdded(entry)` and never touches the list. An entry added while the list is still loading is dropped by `LoadingSources`: the first load already includes it. Why: the add button sits in the header and the list in the side bar, two siblings that share the reading, so it lives above both in a provider, as the API does in `ApiProvider`. State objects replace conditionals on the reading, as `HealthMark` does with a lookup. The add button is in the header, at the right, because adding a source is an action of the app, not of the list.
