# The CLI builds its client on every call

`AddressedClients` builds the generated client on every call from the current address (`BackendChoice`) and the pass in `PassStore`, and adds the `Authorization: Bearer` header only when a pass is kept. `ApiSorzs`, `ApiUsers`, `ApiSorzs` and `ApiHealth` take it through the `Clients` interface. `AddressedLogin` builds its own client from the address and delegates to `ApiLogin`: logging in needs no signature, and a kept pass must not travel with it. Why: `login`, `logout` and `backend <address>` change the pass and the address while the prompt is open, so a client built once at start would sign with a stale token or call a stale service. `BackendChoice.current()` is public for this reason. Names: `BackendChoice` picks the first origin that has an address; `Addressed*` builds on the address it picked. `Chosen*` was rejected for the clients and the login because they do not choose anything; `Current*` clashes with `current()`; `Fresh*` and `Rebuilt*` name the mechanism, not what the class is aimed at.
