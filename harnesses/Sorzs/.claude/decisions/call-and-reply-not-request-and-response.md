# Call and Reply, not Request and Response

The application message pair is `Call` (header `callId`, body) and `Reply` (header `callId` and `status`); the JSON transport is `JsonTransport`. Why: `Request` and `Response` already mean HTTP in `Operation.serve`, and "envelope" read as transport. `callId` replaces `requestId` on the wire for the same reason. `Invocation`/`Outcome` was the runner-up. The word "request" or "response" never names an application-layer concept: `InvalidRequestError` became `InvalidBodyError` and `INVALID_REQUEST` became `INVALID_BODY` (the other `Invalid*Error`, `InvalidCallError`, is the malformed-Call 400); OpenAPI schemas are `CallHeader`, `ReplyHeader`, `HealthCheckCall`, `HealthCheckReply`. HTTP `Request`/`Response` stay only at the transport edge.
