# Users come from one SEED_USERS variable

The users are read from `SEED_USERS`, a comma-separated list of `username:password[:role]` pairs (`xaviuzz:p1casso:admin,ana:pueblos` in development and e2e). The role is `admin` or `user`; a pair with two fields is a `user`; any other role refuses the start. It replaces `SEED_USER` and `SEED_PASSWORD`, and the backend refuses to start without it. Why: `src/` holds no literal credentials, and one variable grows with the users, and with a role as one more attribute of the same user, where a variable or a file per user or attribute would multiply names in every Compose file. A users file was rejected: it adds a file to mount for two users. Only `admin` and `user` exist; finer permissions wait for a real need. A password with a comma or a colon is not supported; the dev passwords have none.
