# Body is an object; Call answers for itself

`Body` wraps the input fields and offers `requireText(field)`, which throws `InvalidBodyError("<field> is required")`; `InvalidBodyError` lives in `call/` beside it. `Call` keeps `callId` private and builds its own `Reply` through `ok(result)` and `failure(code, message)`. Why: tell, don't ask; no code reads raw fields or the call id to assemble a reply. `Call.runOn(operation)` (the call runs the operation and `body` becomes private) was weighed and deferred. Today handlers read the body through `call.body`, with `requireText` and `optionalText`, and the error-to-code mapping already lives in `Call.failureFrom`. Making `body` private is the only part still open.
