# A sorz has a specific provider or the generic one

The provider that searches a sorz is part of what the list and the census show: a sorz with a specific provider (today Reddit) is marked, one with the generic provider is not, and the census can be filtered to the generic ones, to find sorzs that still lack a better way to be searched. The generic provider is the one that satisfies every sorz; docs, contract and code call it generic, not Google, because Google is only how it answers today. The backend decides the provider and says it in the list and census replies as an identifier (`reddit` or `generic`, never null: `generic` is the absent case); the frontend never repeats the rule about addresses and turns the identifier into the text to show. The mark is one for all specific providers, until a second provider needs its own icon. The filter acts in the browser on the rows read, off by default and not kept. Why: the rule about which sorz a provider satisfies lives once, in the backend, next to the search, so the mark can never disagree with the result. The CLI gets the field through the contract but shows nothing new.
