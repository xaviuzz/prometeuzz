# Frontend API calls go through one CallSender

`Albums`, `Photos` and `UserAlbums` receive one `CallSender` built by `Api`; it owns the client and the session, builds the call header, catches failures into `INTERNAL_ERROR` and turns a reply body into `ApiAnswer<Ok>`. An endpoint passes how to send (a function taking the client and the header) and how to read the ok body. Why a class and not a function taking a reader: it owns two collaborators, and `Api` is already the composition root. Why not `Call`: in the contract `Call` is the request message ([Call and Reply, not Request and Response](call-and-reply-not-request-and-response.md)). Why a send function and not a path: the generated client types each path separately, and a generic path forces casts. One `ApiErrorCode` and one `ApiAnswer<Ok>` replace the per-endpoint aliases. `HealthCheck` stays outside: its result is `"ok" | "error"`, with no code and no ok body to read.
