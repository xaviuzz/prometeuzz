# Sorz and list entry are separate concepts

`domain/sorz/` holds the sorz (a UUID the backend generates, the address, and the title and favicon learned from the page). `domain/sorz-list/` holds the list and its entries (a sorz and the user's name). Each user's list refuses a repeated address (`registration-order-body-page-address-name`); reusing a known sorz for a second user waits for a store of sorzs apart from the list (`docs/sorz.md`, open questions). Name uniqueness lives in the list, and names are compared ignoring case, because the list must not show two entries that look the same. Why: the project description says the sorz is the same for anyone and the name belongs to the user; each has its own rules (`docs/sorz.md`, `docs/sorz-list.md`). Every entry carries its owner (`each-entry-row-carries-its-owner`).
