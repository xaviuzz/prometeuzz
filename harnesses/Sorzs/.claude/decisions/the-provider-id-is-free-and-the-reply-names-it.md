# The provider id is free and the reply names it

`provider` in the sorz entry and in each sorz of the census is a free string, the id; the contract no longer lists the ids. Both carry a required `providerName`, the name the sorz is searched by: `Reddit`, `Wikipedia`, `Geek Feminism`, `Appropedia`, `Generic`. The backend `SearchProvider` answers `name()` beside `id()`, and the add, list and census replies emit both. `ProviderId` stays a closed union in the domain. Why: with an `enum`, every new provider changed the contract, copied it to two repos and regenerated both clients, for no information the frontend could use. The backend decides the provider, so it says how to call it. A contract test compares route names only, so the `enum` never guarded the schema; `generate:check` guards the copies. The change is additive, so the CLI and older readers of `provider` are unaffected. Companion: `the-frontend-has-one-provider-class-and-composes-the-hint`. See `a-sorz-has-a-specific-provider-or-the-generic-one`.
