# A refused file carries its rejection code

`UnreadableImageError`, `UnsupportedFormatError` and `TooLargeError` extend `RefusalError`, which carries its `RejectionCode`, as `CallError` carries its `ErrorCode`. `RejectionCode` lives in `src/photo/`, not in `Reply.ts`: a refused file does not fail the call. `Picture.read` refuses bytes over 25 MB before reading them as an image, so the whole judgement by bytes has one owner. `PhotoUpload` gathers kept photos and refused files in an immutable `UploadOutcome`: each kept or refused file returns a new outcome, so no helper changes what it receives, and the last one answers as the reply body; any error that is not a `RefusalError` still rises to `INTERNAL_ERROR`. Why: the upload mapped errors to codes, held the size limit, and filled two arrays through the arguments of its helpers.
