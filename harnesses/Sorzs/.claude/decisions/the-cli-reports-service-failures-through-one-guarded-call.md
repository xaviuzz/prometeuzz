# The CLI reports service failures through one guarded call

The API wrappers (`ApiSources`, `ApiUsers`, `ApiSorzs`, `ApiHealth`) turn a refusal into `ServiceRefusal` and a forbidden answer (HTTP 403 or the `FORBIDDEN` code) into `ForbiddenAnswer`; a network failure passes as the `TypeError` it is. Every command runs its call inside `GuardedCall`, which writes a refusal's message to the error output, calls `Session.forbidden` for a forbidden answer and says "cannot reach the backend" for a network failure. Why: ten commands share one failure policy, so a command holds only its own output and a new one inherits the policy by using the guard. The domain stays free of the generated client's `CallRefusedError`. Repeating the `try` in each command was rejected: ten copies of the same three branches.
