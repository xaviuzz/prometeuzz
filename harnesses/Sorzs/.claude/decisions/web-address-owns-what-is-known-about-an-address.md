# WebAddress owns what is known about a web address

`WebAddress` in `domain/source/` holds the text of an address and answers `isValid` (http or https), `prefixes`, `site`, `equalsIgnoringFinalSlash` and `resolve`. `SourceAddress` holds one and keeps only its reaction to an invalid one (throw); `FaviconAddress` keeps its own (fall back to `none()`); `CandidateAddresses`, `HtmlHead` and `HttpPageReader` ask it instead of building a `URL`. `resolve` returns an address that is not valid when the reference cannot be resolved, never `null`. Why: the protocol rule and the `URL` handling were written twice in the domain and three times in infrastructure; one owner keeps the rule in one place, and the callers tell it what they need (same null-object reasoning as `a-missing-part-is-a-null-object-not-null`).
