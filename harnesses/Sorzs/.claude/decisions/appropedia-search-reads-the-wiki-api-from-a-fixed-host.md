# Appropedia search reads the wiki API from a fixed host

The provider is for one wiki. Its id is `appropedia`, its name `Appropedia`, it qualifies with `DomainQualificationStrategy("appropedia.org")` (so `www` and any other subdomain count, as with Reddit and Geek Feminism) and it always asks `https://www.appropedia.org/w/api.php` for ten results, whatever host the entry holds. Each call is cut at 3 seconds. A cut, a non-success status or an unreadable body means the sorz did not answer (`SearchFailedError`); no hits is an empty result. There is no slow-down memory, the User-Agent reuses `WIKIPEDIA_CONTACT`, and no e2e scenario is added. Why: `appropedia.org` answers 301 to `www`, so a fixed host never depends on following a redirect. The API is read because the HTML search is not meant for programs. Ten results, 3 seconds, no memory and the shared contact repeat `geekfeminism-search-reads-the-wiki-api-and-fails-as-wikipedia-does`, `geekfeminism-has-no-slow-down-memory` and `the-wikipedia-contact-also-identifies-sorzs-to-geekfeminism`, so no new number or variable is invented. Subdomains other than `www` are accepted without checking that they share this API. Findings: [appropedia-api.md](../reference/appropedia-api.md). Rules: `docs/appropedia-search.md`.
