# A CLI command declares who may use it

Each command in the registry carries an `Access` strategy: `AnyoneAccess`, `SessionAccess` or `AdminAccess`, which answers whether a given pass may use it. In prompt mode the registry asks the kept pass on every call, and `lines()`, `names()` and the lookup of a name keep only the commands whose `Access` allows it, so `help`, Tab and the unknown-command answer agree. In command mode the same `Access` runs before the service is called and, when it refuses, the command fails with "enter with login" or "needs the admin role". Why: one declaration per command feeds the three places that must agree, and a command added later is hidden or shown with no further wiring. The role is read from the kept pass, as the prompt already does; a role changed elsewhere is found out by the service's forbidden answer, which forgets the pass as before. A refresh call for the role was rejected: it needs a new operation to save one re-entry.
